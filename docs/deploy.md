# Демо-стенд на внешнем сервере

Цель: жюри открывает ссылку и работает с живым прототипом, даже если у них не получится запустить Docker локально.

## Что нужно

Виртуальная машина с Ubuntu 22.04 или 24.04: минимум 2 vCPU, 4 ГБ RAM, 20 ГБ диска, публичный IP, открытые входящие порты 22 (SSH) и 80 (HTTP). Подойдёт любой провайдер, например:

- **Yandex Cloud** — новым пользователям даётся стартовый грант на 60 дней; его хватает на небольшую ВМ на время хакатона.
- **Cloud.ru Evolution free tier** — бесплатная ВМ 2 vCPU / 4 ГБ / 30 ГБ, но с долей vCPU до 10%: стенд работает, а первая сборка образов идёт заметно дольше. Публичный IP оплачивается отдельно, на него можно потратить приветственные бонусы.

Условия бесплатных тарифов меняются — проверьте их на сайте провайдера при регистрации.

## Шаги

```bash
# 1. С вашего компьютера: скопировать архив на сервер
scp smart-credit-cabinet.zip ubuntu@<IP>:~

# 2. На сервере
ssh ubuntu@<IP>
sudo apt-get update && sudo apt-get install -y unzip
unzip smart-credit-cabinet.zip && cd smart-credit-cabinet
bash scripts/deploy.sh          # ставит Docker, генерирует секреты, собирает и запускает
```

Или вместо архива — `git clone <ваш репозиторий>` (так на сервере будет та же версия, что сдаётся на проверку).

Через 5–10 минут скрипт выведет адрес `http://<IP>`. Проверка: `sudo docker compose exec api python -m app.smoke`.

## Что открыто наружу

Только порт 80: интерфейс, `/api`, Swagger на `/docs`. База данных, API на 8000 и симулятор на 8090 доступны лишь внутри Docker-сети. Секреты (`JWT_SECRET`, пароль БД) генерируются случайно и лежат в `.env` на сервере; в репозиторий этот файл не попадает.

## Перед показом

```bash
bash scripts/reset-demo.sh      # вернуть исходные демо-данные
```

Обновить стенд после новых коммитов: `git pull && bash scripts/deploy.sh`.

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `pull access denied`, `403` или таймаут при скачивании образов | Включите зеркало Docker Hub: добавьте в `/etc/docker/daemon.json` строку `{"registry-mirrors": ["https://mirror.gcr.io"]}`, выполните `sudo systemctl restart docker` и запустите `deploy.sh` снова |
| `!override` / `!reset` — ошибка разбора compose-файла | Обновите Docker: `curl -fsSL https://get.docker.com \| sudo sh` (нужен Compose 2.24+) |
| Сайт не открывается извне, но `curl localhost` на сервере работает | Откройте порт 80 в группе безопасности / файрволе провайдера |
| Страница открывается, но заявки висят на «Заявка отправлена» | `sudo docker compose logs worker --tail=100` — обычно воркер ещё стартует; на слабой ВМ подождите минуту |
| Не хватает памяти при сборке | Добавьте swap: `sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile` |
